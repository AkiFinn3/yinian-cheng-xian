## 一、本次目标

**做：**

1. **境界体系**：每个境界分「初期 / 中期 / 圆满」三阶，圆满后可**破境**进入下一境界
2. **功法分境界**：每个境界有自己专属的功法池，境界提升后低阶功法不再出现
3. 功法**叠加**：同一功法可重复获得，效果累加
4. 功法池从 3 种扩到 **16 种**（4 境界 × 4 种）
5. 破境时获得**专属破境功法**（三选一，强度高于普通功法）

- ❌ 不加波次/计时（阶段 10）
- ❌ 不加首领（阶段 10）
- ❌ 不改妖兽系统（阶段 8 已定稿）
- ❌ 不加存档（阶段 11）
- ❌ 不做功法进阶组合（本阶段先做叠加，组合留到后续）

## 四、关键技术改动

### 4.1 现有代码的问题

当前成长系统只有 `level` 一个整数（`main.gd:78`），功法硬编码在 `choose_skill()` 的 `match` 里（`main.gd:366-372`）。

**扩到 16 种功法 + 境界体系，必须重构数据结构**，否则 `match` 会变成 19 个分支。

### 4.2 新的数据结构

```gdscript
# 境界表：名称、三个小境界、修为阈值、功法池、破境功法
const REALMS := [
    {
        "name": "炼气",
        "stages": ["初期", "中期", "圆满"],
        "xp": [30, 45, 55],          # 初期→中期 / 中期→圆满 / 圆满→破境
        "skills": ["剑气诀", "护体灵气", "疾风步", "凝神"],
        "breakthrough": ["筑基丹成", "灵根淬炼", "气海扩容"],
    },
    ...
]

# 功法表：效果类型 + 数值
const SKILLS := {
    "剑气诀": { "desc": "剑气伤害 +8",  "stat": "sword",   "value": 8 },
    "护体灵气": { "desc": "减伤 +4",    "stat": "armor",   "value": 4 },
    "疾风步": { "desc": "移速 +25",     "stat": "speed",   "value": 25 },
    "凝神":   { "desc": "暴击率 +5%",   "stat": "crit",    "value": 5 },
    ...
}
```

**效果统一用 `stat` + `value` 表达**，`choose_skill()` 只需一个 `match stat:` 分支（4 种属性），而不是每个功法一个分支。

### 4.3 状态变量改动

| 现在 | 改为 |
|---|---|
| `level: int` | `realm_index: int` + `stage_index: int` |
| `next_level_xp: int` | 从 `REALMS[realm_index]["xp"][stage_index]` 读取 |
| `sword_bonus / armor_reduction / speed_bonus` | 保留，新增 `crit_bonus` |

### 4.4 新增变量

```gdscript
var realm_index: int = 0        # 0=炼气 1=筑基 2=金丹 3=元婴
var stage_index: int = 0        # 0=初期 1=中期 2=圆满
var crit_bonus: float = 0.0     # 暴击率加成
var breakthrough_pending: bool = false   # 是否在破境界面
```

### 4.5 妖兽难度适配

`pick_enemy_type()` 现在用 `level` 算难度。改为用**总进度**：

```gdscript
var progress: int = realm_index * 3 + stage_index   # 0..11
var level_bonus: int = mini(progress, 6)
```

保证境界越高，厚血妖兽越多。

## 九、需要开发者确认的三个问题

1. **境界数量**：4 个（炼气/筑基/金丹/元婴，12 小境界）是否合适？还是先做 3 个（9 小境界）？
2. **破境方式**：目前设计是「修为满自动触发破境界面 + 专属三选一」。是否要改成「必须击败精英妖兽才能破境」（更有仪式感，但要等阶段 10 的精英系统）？
3. **低境界功法**：境界提升后，低阶功法**不再出现**（本稿采用）。是否希望保留少量低阶功法作为"保底选项"？
