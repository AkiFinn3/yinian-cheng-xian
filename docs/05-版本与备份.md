## 三、备份方式（双重保险）

### 第一层：Git（推荐，日常用）

```bash
# 查看当前状态
git status

# 查看历史
git log --oneline

# 提交新版本
git add -A
git commit -m "v0.2.0 阶段8：三种妖兽"

# 看某个版本改了什么
git show <提交号>

# 撤销未提交的改动（回到上次提交）
git checkout -- .

# 回到某个历史版本（谨慎）
git checkout <提交号>
```

### 第二层：文件夹副本（每次阶段完成时）

```bash
cd /Users/yu/Documents/Game
cp -R yinian-cheng-xian "备份/v0.2.0-$(date +%Y%m%d)-阶段8-三种妖兽"
```

**命名格式：** `v版本号-日期-阶段-简述`

## 四、变更记录

### v0.2.0 · 2026-10-28 · 三种妖兽（阶段 8）

**修改了什么：**
- 新增 `ENEMY_TYPES` 常量数据表：妖狼 / 疾风雀 / 岩甲兽
- 新增 `pick_enemy_type()`：按等级加权随机选择妖兽类型
- `spawn_enemy()` 从数据表读取速度、大小、血量
- `kill_enemy()` 按类型给不同修为，提示文案带妖兽名
- `update_enemy()` 接触伤害按类型计算
- `_draw()` 妖兽颜色按类型取，血条宽度自适应，头顶显示妖兽名
- 头部注释更新为"第八阶段"

**为什么修改：**
- 只有一种妖兽导致战斗重复，需要基础难度曲线
- 为阶段 9（功法）和阶段 10（波次）打基础

**通过的测试：**
- ✅ `--headless --check-only` 语法校验
- ✅ 运行时测试：3000 次生成属性全部匹配数据表
- ✅ 权重实测：Lv1 妖狼 54.3% / 雀 30.5% / 岩 15.2%；Lv7 妖狼 14.9% / 雀 40.7% / 岩 44.3%
- ✅ 击杀奖励实测 10 / 8 / 25 正确
- ✅ 主场景 headless 运行 300 帧无报错
- ⬜ 实机验收（待开发者执行）

**已知问题：**
- 仍只能同屏 1 只妖兽（多妖兽需阶段 10 重构）
- 数值未经真人手感验证，可能需要 v0.2.1 调整

## 五、回滚方案

### 场景 A：刚改坏了，还没提交

```bash
cd /Users/yu/Documents/Game/yinian-cheng-xian
git status          # 确认哪些文件被改了
git checkout -- .   # 全部撤销
```

### 场景 B：已经提交了坏版本

```bash
git log --oneline           # 找到上一个好版本的提交号
git revert <坏提交号>        # 生成一个反向提交（推荐，保留历史）
```

### 场景 C：Git 也乱了

直接从文件夹副本恢复：

```bash
cd /Users/yu/Documents/Game
cp -R "备份/v0.1.0-20261028-阶段7-完整可运行版/scripts/main.gd" yinian-cheng-xian/scripts/main.gd
```

**恢复后立刻重新运行游戏确认。**
