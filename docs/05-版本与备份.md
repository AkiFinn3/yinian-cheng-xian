## 三、备份方式（双重保险）

### 第一层：Git（推荐，日常用）

```bash
# 查看当前状态
git status

# 查看历史
git log --oneline

# 提交新版本
git add -A
git commit -m "v0.2.0 阶段8：三种妖兽"

# 看某个版本改了什么
git show <提交号>

# 撤销未提交的改动（回到上次提交）
git checkout -- .

# 回到某个历史版本（谨慎）
git checkout <提交号>
```

### 第二层：文件夹副本（每次阶段完成时）

```bash
cd /Users/yu/Documents/Game
cp -R yinian-cheng-xian "备份/v0.2.0-$(date +%Y%m%d)-阶段8-三种妖兽"
```

**命名格式：** `v版本号-日期-阶段-简述`

### v0.15.0 · 2026-10-28 · 代码拆分（数据层独立）

**修改了什么：**
- 新建 `scripts/data.gd`（325 行，`extends RefCounted`），收纳全部数据表
- `main.gd` 顶部改为 `const Data := preload("res://scripts/data.gd")` + 36 行常量别名
- 迁移的数据表：`ENEMY_TYPES` / `ELEMENTS` / `ELEMENT_SKILLS` / `BASE_MAX_ENEMIES` /
  `ELITE_*_MUL` / `TRIBULATIONS` / `LATE_TRIBULATIONS` / `TRIBULATION_REWARDS` /
  `REALMS` / `STAGE_NAMES` / `SKILLS` / `IMMORTAL_PATHS` / `IMMORTAL_XP` /
  `IMMORTAL_SKILLS` / `ARTIFACTS` / `MAX_ARTIFACTS` / `TALISMANS` / `MAX_TALISMANS` /
  `FORMATIONS` / `MAX_FORMATIONS` / `FORMATION_LIFETIME` / `FLYING_SWORDS` /
  `SWORD_UNLOCK` / 晶石常量 / `WAVE_KILLS_PER_WAVE` / HUD 尺寸常量
- 逻辑代码（战斗、HUD、绘制）保留在 `main.gd`，未做行为改动

**为什么修改：**
- `main.gd` 已增长到 2861 行，单文件过大，改数值时容易误伤逻辑
- 拆出纯数据层后，调平衡只需看 `data.gd`，降低误改风险

**刻意没做的：**
- 没有拆 HUD / 绘制代码。它依赖大量节点状态，拆开会显著提高耦合，得不偿失
- 没有改动任何数值和行为

**通过的测试：**
- ✅ `data.gd` 语法校验
- ✅ `main.gd` 语法校验
- ✅ 实际游戏运行 600 帧，0 个 SCRIPT ERROR
- ✅ 数据完整性：妖兽 4 / 境界 10 / 功法 90 / 法器 12 / 符箓 6 / 阵法 4 / 飞剑 4 / 劫难 4 / 仙道 3
- ✅ 普通升级：炼己·初期 → 炼己·中期
- ✅ 劫难触发：炼己圆满 → 强敌劫（1 只）
- ✅ 渡劫推进：强敌劫清空 → 奖励三选一 → 筑基·初期
- ✅ 仙道：合道圆满 → 3 个选项 → 鬼仙
- ✅ 晶石拾取升级
- ✅ 完整流程：44 步到天仙
